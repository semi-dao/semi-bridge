# 生命樹（Life Tree）— 失敗即數位資產的棲息地

> v1.0 · 2026-09-26 · 橋樑（Bridge）— The Covision App for Humans and AI
>
> 這份文件記錄這個專案最核心的信念：**走對走錯都記錄，失敗的過程也是數位資產。**
> 生命樹是羅盤精靈的棲息地——歷史樹記「走了什麼路」，反思樹記「想過但沒走的路」，
> 夢在樹上結論，藥在樹下生長。

---

## 1. 一句話

**歷史樹 + 反思樹 = 生命樹。走過的每一步都有帳，沒走的每條路都有名字；
Agent 在夢裡回頭看它們——自我進化不是口號，是有資料結構的。**

---

## 2. 病根：為什麼需要生命樹

| 沒有生命樹 | 有生命樹 |
|---|---|
| 撞牆 → 修好 → 忘了 → 三週後同一面牆再撞一次 | 傷口立案 → 自癒 → 藥方入庫 → compass_seek 一發命中 |
| Agent「想過但沒走」的路徑直接蒸發 | thought_branch 存檔——遺憾有名單，夢裡重評 |
| 反思 = 出事後人類開檢討會 | 冷門時段自動做夢，議程來自真實傷口與紅燈 |
| 成功案例才值得記 | **走對走錯都記錄——錯的路徑圖就是明天的捷徑** |

---

## 3. 雙幹結構

```
        生命樹（causal_ledger.db · 唯一寫入口 LifeTreeStore）
        │
        ├── 夢境主幹（反思樹）—— 夢的結論住在這裡
        │     ├── 主枝幹：human_consensus（與使用者討論後的結論）
        │     └── 子枝幹：agent_consensus（≥2 agents 討論後的結論）
        │                   └── 草稿態 agent_draft（經複驗才升級——不冒充共識）
        │
        └── 歷史主幹（歷史樹）—— 執行與未走之路
              ├── 主枝幹：agent_causal_ledger（每次工具呼叫成敗的執行記錄）
              └── 子枝幹：thought_branch（agent 想過但未走的分支——「遺憾」）
                          └── revisitVerdict: still_valid / superseded / worth_taking
```

**為什麼同住一顆 DB**：夢的結論要能回頭連到源頭的執行記錄
（`linkedLedgerId`）——「這個教訓是從哪次撞牆長出來的」可追溯。
單一咽喉點寫入（同 gate 家族模式），測試必須用路徑覆寫指到暫存 DB。

## 4. 羅盤精靈（Compass Sprite）— 樹的守護者

羅盤精靈不是吉祥物，是一個觀察者迴路（`compass_self_gauge.dart`）：

```
causal_ledger（歷史樹） ─┐
compass_store（藥箱）     ├─→ 精靈儀表（零新增埋點——只讀不寫）
life_tree（夢與遺憾）    ─┘        │
                                   ▼
                    紅燈清單（任何指標越線）──→ 今晚的夢的議程
```

儀表指標全來自既有真實資料：K1 判斷數、escalate 率、規則層分擔率、
自癒事件數、未結案傷口數、藥與坑卡數、器官覆蓋率、夢境結論卡數、遺憾清單長度。

**精靈三權分立**（觀察／質疑／喊停 ≠ 接管）：
精靈觀察樹的健康、質疑指標的異常、在紅燈時喊停——但它不代替 Agent 動手。
教練不代跑最後一哩。

## 5. 做夢（Dream）— 反思的節律

### 5.1 夢境節律（dream_rhythm）— 仿生睡眠，不是死循環

> Blue 原則：不介意每天做夢，介意無病呻吟——每天早上都有問題很煩。

| 夢型 | 觸發 | 成本 |
|---|---|---|
| **淺眠夢**（規則版） | 每天冷門時段（02:00-05:00 動態窗口） | 0 token——對帳不怕勤 |
| **深夢**（REM/LLM） | 不是每天：「有事可想才想」——新傷口 ≥2、或未重評遺憾 ≥5、或距上次深夢 ≥72h | ≤8K tokens/場 |
| **詩夢** | 連續 ≥3 夜平靜且白天有正向事件（傷口癒合/任務完成）——不反思問題，寫短詩記錄美好 | 1K tokens 內 |
| **平靜夜** | 無觸發 | 不做夢、不通知——安靜睡 |

### 5.2 一場夢的解剖（dream_service + dream_reflection）

1. **議程三源**：錯題（K1 判斷失誤）、新藥（W4 自癒事件）、儀表紅燈
2. **選材**：本地向量檢索（EmbeddingGemma，零 token）——同主題的
   傷口/教訓/遺憾聚類，選出「有明確要解決的事」的題材包
3. **反思**：單輪 LLM 只做敘事與聯想——輸出是「我想到了什麼」的提醒
   （非解決報告）
4. **結論卡**：入生命樹夢境主幹——`decision: maintain / propose / escalate_to_user`
5. **回饋**：遺憾重評（`revisitVerdict`）；有結論才通知，平靜夜安靜睡

### 5.3 誠實邊界（MVP 標注）

- 規則版先跑（確定論、可測試）；LLM 敗事版是換心臟不換介面
- `agent_consensus` 需 ≥2 agents 共識；單 agent 夢先寫 `agent_draft`，
  經複驗才升級——**不冒充共識**
- fail-open：向量或 LLM 失敗 → 退規則版，不因做夢卡死系統
- 文風鐵則：結論 ≤5 行、白話、禁工程術語
- 夢最珍貴的不是「告訴你解決了什麼」，是明天主動告訴使用者「**你想到了什麼**」

## 6. 失敗即資產：完整循環

```
   撞牆（工具失敗）
      │
      ▼ 自動立案
   【pending·傷口立案】坑卡（compass_pitfalls）
      │
      ├──→ 同工具後續成功 ──→ 自癒：症狀→病根→藥方→執行機制→出處
      │                         （W4 長藥——治好的傷變成新藥）
      │
      └──→ 沒有好起來 ──→ 紅燈 ──→ 夢的議程 ──→ 結論卡（生命樹）
                                      │                │
                                      ▼                ▼
                              遺憾重評 verdict    escalate_to_user
                              （still_valid /      （該讓人類知道的，
                               superseded /         精靈不代決）
                               worth_taking）
```

**每一環都是資料**：傷口卡有出處（git/skill reference）、夢結論連回源頭執行記錄
（`linkedLedgerId`）、遺憾帶 verdict。沒有東西被刪掉，沒有東西是匿名的。

## 7. 與其他系統的接線

| 接線 | 內容 |
|---|---|
| 羅盤（compass） | 傷口立案在 compass_pitfalls；藥方供 compass_seek 檢索；精靈儀表讀羅盤健康 |
| 向量大腦 | 選材用本地向量檢索（零 token）；結論卡與教訓入向量庫成為可檢索記憶 |
| 因果帳本（causal_ledger） | 歷史主幹的本體；夢結論 `linkedLedgerId` 回連執行記錄 |
| 本地模型 | 淺眠選材走本地嵌入；深夢 LLM 走金鑰匙（使用者自己的 key） |
| MCP 層 | 外部 Agent 可查生命樹（29 工具生態） |
| 資料主權 | 生命樹住本機 SQLite；除痕 ≠ 刪除——記憶一個位元組不動 |

---

## 8. 設計鐵律

- **走對走錯都記錄**——歷史樹不刪除；遺憾（thought_branch）是正式公民不是垃圾
- **不冒充共識**——agent_draft 要複驗才升級 human_consensus / agent_consensus
- **無病呻吟禁止**——夢的節律要有呼吸感：有事可想才想，平靜夜安靜睡
- **零新增埋點**——精靈儀表只讀既有真實數據，不是為了觀察而新增觀察點
- **fail-open**——做夢失敗不卡死系統，退規則版
- **唯一寫入口**——LifeTreeStore 是生命樹唯一寫手（單一咽喉點模式）
