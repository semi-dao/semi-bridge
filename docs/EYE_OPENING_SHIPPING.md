## 0. 為什麼叫「開光」（LightUp）

傳統雕塑完成時只是物品；開光點眼之後，才是「在場」的靈魂。畫龍點睛同構——牆上的龍再完整，沒有眼睛就不會飛。

這個 App 的「龍身」早已畫好：本地 HTTP 通道上 68 條 route 蟄伏多時——導航、視圖、訊息、向量搜尋全都在。這條龍唯一缺的是眼睛：**外部 Agent 不知道這些門存在、看不見畫面、也點不著按鈕**。

v0.4.0 把這個缺補上。龍開眼的那一刻，Agent 第一次以「使用者」的身份在場於這台機器——不是被遙控的執行器，是能自己看、自己動手、自己驗證的使用者。

**英文名 LightUp**（2026-09-26 拍板）：不是點亮用戶，是點亮 Agent 自己的眼睛。

## 1. 起源：一場截圖之戰

2026-09-25，開源整備需要幾張 README 截圖。人類使用者按 Cmd+Shift+4 三秒完成的事，Agent 撞牆了五輪：

- 開瀏覽器截網頁 → 被瀏覽器的 user-gesture 限制擋下
- 用視覺模型給座標點擊畫布卡片 → 五輪全部失敗
- 系統級視窗操作 → 對 Flutter 視窗靜默失敗
- 最後靠掃描設計系統色碼 + 直接注入系統事件才勉強成功

每一輪撞牆都不是 Agent 笨——是**產品缺口**。人類使用者永遠不會遇到這些斷點（因為對人太簡單），但 Agent 使用者天天卡死在上面。這五輪撞牆被如實記錄成 8 條設計輸入，成為 v0.4.0 的全部範圍。

**這是我們的核心方法論：Agent 的每一次撞牆都是產品需求。** 失敗紀錄不是垃圾，是規格書。

## 2. 設計哲學：五條不變式

1. **表單即對話** — Agent 的介面不該是人類表單的複製品；語意化 API（「看畫布」「點儲存」）優先於座標模擬
2. **紅線是篩選器** — 權限邊界用於過濾請求（能做什麼先查清楚），不是事後攔截（撞了才知道）
3. **證據鏈** — 每個 Agent 操作可回溯到工具呼叫紀錄
4. **全程可回放** — 操作日誌（oplog）思路，任務可重演
5. **零人類介入** — Agent 任務閉環不強制等人類；人類介入是選項，不是必經關卡

## 4. 驗收基準：同一任務重跑

用截圖之戰的原任務重跑（拍「首頁 + 畫布 + 星系」三張圖）：

- **v0.3**：15+ 輪、跨 4 種通道（瀏覽器、osascript、視覺座標、系統事件）、大量失敗重試
- **v0.4.0 目標**：3 輪內、全部走官方通道、零座標 hack

這個 benchmark 天然可回放（oplog），也是「Agent-as-User」最好的 demo 素材。
