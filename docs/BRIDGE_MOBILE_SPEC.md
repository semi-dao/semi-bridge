## 1. 靈魂定位（憲法條款）

1. **一個共視宇宙、兩種版本**：
   - **團隊版**——連自己電腦上的 Bridge 世界（Agent 在畫布上幹嘛、數位資產產出）
   - **農場版**——連農場主機（Jetson 級）的封閉世界（魚菜共生專家模型＋農場數據）
2. **農場主不是二等用戶**：每個農場主夥伴都是**頭號玩家、一等公民、最好的使用體驗者**（Blue 原話 2026-10-30）。體驗標準與團隊版完全一致。
3. **同一個骨架同步長**：不是先內後外、不是一殼兩 App——一套手機底座，兩版同時演進。

## 2. 手機是什麼

4. **手機不運算**——它是窗，連向一台「主人翁主機」（團隊=自己的 Mac、農場=農場的本地 AI 主機）。
5. **完整遙控**：能看、能聊、能下指令（含花錢／危險動作）。**既有確認框鐵則不因手機豁免**——手機上按 ▶ 照樣跳確認框（對位 AGENTS.md「花錢任務▶前必跳確認」）。
6. **配對**：掃主機螢幕上的 QR Code（第一次見面認親）。**配對成功後主機發長期裝置 token（存 Keychain/Keystore），重連憑 token 自動握手，token 失效才要求重新掃 QR；重新配對限 LAN 內進行**（紅隊 #8 補全）。

## 3. 首頁資訊架構（兩版同一結構）

7. **「生活感／呼吸感」首頁**——憲法級條款：
   - 首頁是一頁**摘要**：農場版=魚/菜/警示/AI一句話；一般版=使用者相關資料與數位資產產出
   - 內容會**輪播**（首頁是活的、會呼吸）
   - 使用者可**自訂**顯示內容
   - 包含**拍板窗口**（決策待確認事項的直接入口）
   - **禁止**：冰冷的任務清單、密密麻麻的對話文字列表
8. **畫布共視**住在更深的層（詳情/第三層），不是第一畫面——共視精神保留，但入口設計尊重手機的觀看習性。

## 4. 資安架構（農場版核心）

### 4.1 保密分層

| 層 | 內容 | 去處 |
|---|---|---|
| 🔒 機密層 | 專家模型、數據分析演算法、產量報表帳本 | **鎖死在 Jetson 硬體內，永遠不出家門** |
| 🌐 開放層 | 通知推播、互動談話、自然語言訊號 | 可走網路——滿足手機連網與出門監工 |

（Blue 原則 2026-10-30：「要保密的是專家模型與數據分析演算法，通知推播與互動談話不算技術機密」）
（v0.4 紅隊 #4 界定：「不出家門」約束範圍 = 專家模型權重與原始演算法 + Jetson 上的帳本原始資料；農場數據經 Mac mini 雲端 API 的外流路徑由 DataPathGate 分級管控，於 DataPathGate 註冊「農場數據」為黃燈類別，用戶自選雲端 = 自擔開放層風險）

### 4.2 實體鑰匙（NFC 紀念品）——農場版專屬硬體（Blue 拍板 2026-10-31 選 A）

> 開源團隊版**無 NFC 鑰匙**：以配對 token＋可選 TOTP 取代。本節僅適用農場版。

9. **內芯**：安全晶片級 NFC（YubiKey 級、防隔空複製）——**一般 NFC 貼紙可被克隆，禁用**。
10. **外形**：做成**紀念品擺飾**，坐鎮主機旁的感應座（NFC 感應距離僅數公分，本來就要常駐）。
11. **設計邏輯**：晶片要真（防複製）、包裝要騙人（防猜測）——小偷抱走主機沒用，也猜不到擺飾是鑰匙。

### 4.3 轉譯鏈

12. **轉譯鏈（v0.4 修訂：角色切開）**：NFC 鑰匙保護 **Jetson 機密層的靜態加密與解密閘**——機密層資料以鑰匙衍生金鑰做靜態加密（LUKS 等價），開機需感應解鎖，拔碟離機即密文；**手機 ⟷ Mac mini 通道由配對時協商的通道金鑰（TLS）保護，與 NFC 鑰匙脫鉤**；開源 LLM 負責把專家模型輸出講成自然語言。
    - 「呼叫與通知經鑰匙轉譯（否則亂碼）」的原始構想**僅適用於 Jetson 內部與 Jetson→Mac mini 情報環節**；APNs 推播屬 §4.1 開放層明文（Blue 已接受），不在鑰匙保護範圍。
13. **開源 LLM 當嘴巴**：主機上用開源 LLM 把專家模型輸出轉譯成自然語言與農場主溝通。

### 4.4 反蒸餾防護（說話風格憲法）

14. **專家模型只吐「結論」，永不吐「怎麼算的」**。
15. 理由一律用**比喻式＋自然語言**（例：「魚池最近像加班太多的員工，需要放個假（換水 20%）」）——比喻層本身就是反黑箱萃取防護：錄一萬句對話，逆向出來的是文學，不是演算法。
16. 理由可含**聖經真理，但避免基督徒術語**——用普遍性真理講法（Blue 原話 2026-10-30：「包含聖經真理（避免基督徒語言）」）。
17. 殘餘風險評估（Blue 判斷）：即使有人不惜成本做逆向蒸餾，得到的也只是模糊的可能數據，攻擊成本遠高於價值——**接受此殘餘風險，不再加碼**。

## 6. 連線架構（2026-10-30 第二輪拍板）

### 6.1 通訊協議：8787 門面 + 8420 引擎室（Blue 拍板「協議A+巧勁」）

- **Desktop Bridge Gateway（8787 WebSocket）當手機的門面**——考古證實此管線從未死：桌面端每次啟動自動 `_startGateway()`、8 個測試綠、協議含 hello 握手/runtimeSnapshot/capabilityList/長任務生命週期/**taskAwaitingConfirmation（拍板等待推播，v0 當年就埋好）**
- **門後直通 8420 MCP**：gateway 內部把遙控指令轉發成 MCP 工具呼叫（51 個工具白吃，不重寫）
- 分工：8420 留給 Agent 用，手機走 gateway——一個前門、一個引擎室
- ⚠️（紅隊 v0.4 修訂）**「8787」為歷史慣稱；實際埠以配對 QR payload 的 `port` 參數為唯一真相源（目前預設 8790，`DesktopBridgeLocalGatewayConfig.port`），禁 hardcode**
- ⚠️（紅隊 #13/#14）**「gateway 轉發 8420」是全新元件非既有事實**：轉發層 = gateway 進程內 in-process 呼叫（非另開 HTTP）；手機僅開放**白名單子集工具**（清單另行拍板），其餘回「此指令僅限 Agent 本機使用」；手機通道每次工具呼叫過 DataPathGate 分級，與本機 Agent 同一咽喉點——8420 loopback 防禦哲學不因手機通道破功
- 殘檔回收判定：協議三檔（gateway protocol/local gateway/pairing contract）＋8 測試＝**協議層直接回收**；`mobile_bridge_client.dart` 之 QR 解析/重連/心跳邏輯**參考重寫**（UI 與生命週期照 §0 重寫原則）；`ws://` 明文要升級 TLS——**配對時主機出示自簽憑證、App 釘住憑證指紋（TOFU）；DDNS 層主機自動申請 Let's Encrypt；第 3 層 relay 僅盲轉 TLS 位元組流不終結**

### 6.2 出門連線：三層樓梯（Blue 拍板 v0.1 版）

```
第 1 層｜同網直連（預設，永遠優先）
  → 人在家/農場 Wi-Fi 內，零設定零後門
第 2 層｜自開後門（出門主力）
  → 主機開加密埠 + DDNS；App 偵測網路環境，
     能開就一鍵引導開，開不了明講（寧紅字不假成功）
第 3 層｜自架中繼（救生艇，選配）
  → 開源包附 Docker 一鍵自架；SemiDAO 不經營
```

- **v1 已知缺口（Blue 拍板接受）**：社區網路/CGNAT 用戶第 2 層開不了門、第 3 層自架門檻超出一般用戶——文檔明寫「社區網路用戶請搭配 Tailscale 等第三方方案」
- **未來選項**：開源社群真長出需求時，再評估 SemiDAO 經營公共中繼（屆時有真實數據，非現在猜）
- 頭號用戶群影響評估：團隊版 ✓（路由器自管）、農場版 ✓（台灣農舍多為獨立寬頻＋浮動公網 IP，DDNS 即通）；缺口主傷都市大樓開源用戶

### 6.3 第 3 層中繼正式立項（2026-11-12 Blue 拍板「把第 3 層中繼正式立項，照藍圖開工」）

**定位**：Discord 級零設定出門體驗的開源複製——兩端都「往外連」的外部伺服器，但**伺服器是使用者自架的**（Docker 一鍵；SemiDAO 永不經營）。

```
手機 ──往外連──> 使用者自架中繼（Docker，$0~5/月 VPS）<──往外連── 家中主機
                     TCP 盲轉：不解讀、不落地、不終結 TLS
```

**協議（v1，TCP 盲轉）**：
- 中繼開 raw TCP listener（預設 :8791）
- 連上先送**一行 JSON hello**（明文，僅配對用）：`{"role":"host|client","hostId":"…","secret":"…"}`
- `hostId`＝桌面 App 穩定主機 ID；`secret`＝配對時 Qr 發行的**中繼配對金鑰**（與 device token 分開）
- 兩側到齊且 secret 匹配 → **其餘位元組全雙工盲轉**（中繼對應用層協議零理解；TLS 升級後端對端加密，中繼物理上看不到內容——符合 §6.1 紅隊條款「僅盲轉不終結」）
- secret 不匹配 / 30 秒等不到對象 → 斷線（寧斷線不轉錯人）

**部署包**：`tools/relay/`（Dart 單檔伺服器）＋ `Dockerfile` ＋ `docker-compose.yml`（前端掛 Caddy 自動 Let's Encrypt；外側 TLS 先行，端對端 TLS 隨第 2 層工作補上）

**工程分四哩**：①中繼本體＋配對＋盲轉（本 commit）②桌面 gateway 出站連接器（主動連中繼註冊 hostId）③手機端爬樓梯 failover（區網→直連→中繼）④一鍵部署文檔。

### 6.4 主權樓梯論述（2026-11-15 Blue 拍板「替大家搭橋」）

三層樓梯不只是連線 failover，是**主權的明碼標價**——每一層用多少信任換多少便利，都攤在陽光下：

| 樓層 | 連線方式 | 適合誰 | 主權代價 |
|---|---|---|---|
| 第 1 層 | 區網直連 | 在家 | 零——資料不出家門 |
| 第 2 層 | 自架 DDNS＋埠轉發（直連公網） | 主權派、有路由器控制權 | 零第三方，但吃自家網路穩定性（IP 變動/CGNAT/重開機即斷）；技術門檻對租屋/宿舍/公司網路者不可及 |
| 第 3 層 | 官方/自架中繼 relay | 大多數人 | 需信任一台中繼主機（SPEC 設計為盲轉 TLS 位元流、不終結、看不到內容） |

設計原則：
- **不假裝代價不存在**——使用者知道自己在哪一層、付出了什麼（連線狀態顯示樓層）
- **不用一開始選邊站**——同一個 App，主權派有路、便利派也有路，隨時可升降
- 對位資料主權宣言「除痕≠刪除」同構：把選擇權留給使用者，工程上誠實揭露

開源溝通定位：網路界「自架雲端 vs 用別人服務」的老辯論，這裡做成同一個 App 內的可選樓梯——這是本專案對「替大家搭橋」的核心回答。

### 6.5 第 2 層破局：IPv6 直連（2026-11-16 實證）

[11-16 搭橋戰役] CGNAT 時代的第 2 層重生——**IPv6 是電信商被迫給每個人的真公網位址**，無 NAT、無埠轉發、無第三方：

**拓撲**：手機(4G/5G 蜂窩 v6) → 電信骨幹 → Mac(家用光纖 v6)。中間零中轉。

**落地鏈（commit 6b6eaad8 → 0c2dd92c，stamp 1116.0030→1116.0550）**：
1. ASUS 路由器 IPv6 設 `ipv6pt`（pass-through）——dhcp6 模式在上層 Zyxel（中華電信 GPON）不發前綴，是岔路
2. gateway 綁 `anyIPv6` dual-stack（v4 相容不破壞）
3. `LanIpDetector` 增抓全球 v6（2000::/3）進 QR alts
4. QR/parse/endpoint 三處 v6 `[ ]` 包裹處理（unwrap——雙括號是 FormatException 炸彈）
5. `PairedDesktop.altHosts` 持久化候選＋bootstrap 逐候選＋`_doConnect` 輪替
6. `WebSocket.connect` 8s 硬逾時（iOS 系統級 75s 會鎖死輪替）＋重連 2s/4s 封頂
7. token 跨端點 fallback（gateway 簽的裝置憑證不綁來源位址——候選查無 token 借主 host 的）

**已知代價（誠實揭露）**：
- v6 前綴變動（電信商數週~數月）→ 需重掃 QR。主權方案的代價，頻率可接受
- 家用 WiFi 的 RA 廣播不如有線穩（Mac 建議接有線——DGX 有線實證 RA 穩定）
- 蜂窩 v6 入站到家用 v6 的通道通否，待 Blue 實測收尾（App 端三隻蟲已修完：雙括號/75s 逾時/token 鑰匙孔）

**對全人類的意義**：IPv4 的 NAT 污染把「自架服務」變成技術特權；IPv6 把它還給每一個電信用戶——這是第 2 層樓梯對 CGNAT 世代的回答。

## 8. 對話↔任務綁定架構（2026-11-10 Blue 拍板：分支討論閉合）

### 8.1 手機 Tab 定案：四按鈕

**此刻｜對話｜任務面板｜配對**（Blue 2026-11-10 原話拍板）

- **此刻**：滿版骨牌（§3 呼吸感；快照/對話移出——快照在配對、對話在對話）
- **對話**：Discord 式三層——左欄圓標（可自訂圖，固定三類型）→ 中欄列表 → 對話視圖
- **任務面板**：同桌面 App 的專案任務面板（「遙控」tab 廢除，併入此）
- **配對**：快照＋QR 配對管理

### 8.2 對話頁三類型（左欄圓標，固定三種；類型內可新增/刪除/複製）

| 類型 | 左欄 | 中欄內容 | 點入後 |
|---|---|---|---|
| 一般對話 | 💬 | 使用者自訂分類 → 分類內對話（Discord 頻道式） | 一般聊天 |
| 排程任務 | ⏰ | 排程任務卡列表（名稱+狀態燈+下次執行） | **任務綁定討論串**（Semi 秒懂上下文） |
| 專案任務 | 📁 | 專案任務卡列表 | 同上＋可對話中啟動執行；成果推播雙端；**不顯示畫布**（畫布調整=桌面版專屬） |

### 8.3 任務↔對話雙向連動（核心機制）

- 每張任務卡出生自綁一個 conversation（`taskBinding` 欄位，桌面手機同源）
- **對話→面板**：任務對話中 Semi 完成的變更（改啟動時間/排序/內容），任務面板即時反映
  - 例：晨間拾穗對話中改啟動時間 → 面板卡片時間+排隊順序同步變
  - 例：角色形象任務複製→改名「A角色形象」→對話討論執行 → 面板自動長出新卡「A角色形象」
- **面板→對話**：點任務卡=進入綁定討論串（context 自動帶任務 JSON）
- 複製任務=clone 任務+clone 對話上下文 → 討論修改 → 存成同類新卡

### 8.4 成果推播

用既有 gateway push（taskComplete）送手機；狗糧期先做文字摘要，檔案/圖片後續。

### 8.5 手機 Tab 修訂：五按鈕（2026-11-12 Blue 拍板）

**此刻｜對話｜任務面板｜向量資料庫｜配對**

- 新增第五按鈕「向量資料庫」：內容參照桌面 vault_screen 改手機排版（素材牆/清單/標籤三模式＋語意搜尋）
- 手機版檔案預覽**必須開得起 vault 內所有檔案類型**（md/json/jpg/txt/log 等）——點開不可空白
- 任務卡「向量庫預覽」按鈕＝開向量庫 tab 直跳該任務成果檔案位置預覽

### 8.5a 檔案開啟鐵則（2026-11-13 Blue 拍板：「自己能開就開，不能開讓使用者呼叫外部」）

分級策略——**每個檔案都有出路，零死路**：

1. **App 內開**（零摩擦）：圖片（含縮圖管線）、文字（md/txt/json/yaml/原始碼等白名單副檔名）、PDF（原生渲染，milestone）
2. **交棒系統**（App 內麻煩或做不到）：binary 檔（office/音訊/影片/壓縮檔…）→「用其他 App 開啟」按鈕 → 存暫存 → iOS ShareSheet → **使用者自己選手機裡的 App 或瀏覽器開啟**
3. **誠實降級**（寧紅字不假成功）：>20MB 超大檔明講「請回桌面版開啟」；不存在/離線明講原因

實作落點：gateway vaultFile binary 回應攜帶 base64（≤20MB）＋ shareable 旗標；手機端 `_VaultFilePreview` binary 頁 = 檔名＋大小＋外部開啟鈕（`share_plus` ShareSheet）。commit `1ef4948b`。

### 8.6 任務卡規格（2026-11-12 Blue 拍板）

每張任務卡（排程/專案同構）含：

- **資訊**：狀態燈＋名稱＋頻率/下次執行＋**前次執行成敗**（✓成功/✗失敗附原因）＋**產出檔案清單**（檔名+入庫狀態）
- **常駐按鈕**：①向量庫預覽（跳該任務成果位置）②進入討論（綁定討論串）
- **三點下拉**：暫停⇄啟動（**動態——暫停中顯示「啟動」**）／複製成新任務／刪除

### 8.7 已拍板雜項（2026-11-12）

## 9. 對話頁 v2：Claude 2.0 借鑑（2026-11-17 Blue 提案「逆向前端設計」，桌面手機連動改版）

> 來源：Claude 桌面版 2.0 改版（Paula 影音拆解 gfFoxu4V-IA，2026-11-11）。核心洞察：**「一個對話塞太多事就越聊越發散」——解法是把對話變成可編排的樹**。與 §8 任務綁定、因果引擎 L4 狀態分叉同構；我們的版本更強：**子對話直接綁任務卡**（Claude 的只是聊天室）。

### 9.1 四大借鑑（對映我們的地基）

| Claude 2.0 設計 | 我們的版本 | 地基 |
|---|---|---|
| 總管-小隊子對話（一句話開 N 個、縮排側欄、完成回報、可回訪續聊） | 「開小隊」指令：對話中說「分三路處理」→ 自動建 3 個 taskBinding thread（縮排於母頻道下）→ 各自跑 → 完成推播回母頻道「✓ 小隊回報」卡 | §8.3 taskBinding＋三層混合制（11-13 拍板）——縮排只差 parentThreadId 顯示 |
| /btw 側邊聊天（不打斷主線、看得到主線內容、可多開、會保存） | 側窗 thread：臨時 thread 唯讀挂載主 thread 快照 context；回答不寫入主線 | 三層制 schema 零改動（臨時型 conversation） |
| 跨對話彙總（「哪些在等我決定？」→ 讀全部子對話彙總、決定自動派發） | 指揮官視角：母頻道問「待決事項」→ gateway conversationHistory 掃子 thread → 彙總卡 → 回覆派發 | 依賴 gateway conversationList/History（既有殘項，先補） |
| Artifact 成果頁（儀表板/文件、手機可開、分享） | 任務成果預覽（§8.5 已拍板：vault 檔案全類型可開＋外部交棒）＋桌面儀表板渲染 | §8.5a 檔案開啟鐵則已落地（commit 1ef4948b） |

**不借鑑**：Context 用量視覺化面板（token 分區圖）——後置觀察項，非核心動線。

### 9.2 動工順序（Blue 2026-11-17 原則：桌面手機一同連動）

1. **gateway 補 conversationList / conversationHistory request**（殘項清償＋手機對話 tab 地基，一石二鳥）
2. **側欄樹狀化**：`_buildConversationSidebar` 支援 parentThreadId 縮排（13 欄 schema 內容納）；手機對話 tab 同步樹狀
3. **「開小隊」編排**：母對話偵測分派意圖（或明示指令）→ 建 taskBinding 子 thread × N → 完成回報母頻道系統卡
4. **/btw 側窗**（桌面先、手機以浮層）＋ Artifact 式成果預覽強化

### 9.3 手機版排版（Claude 手機端實測拆解，2026-11-17 補查）

Claude 手機（iPhone）的對話頁排版邏輯——**它沒有把手機當桌面的縮小版**：

| 手機排版元素 | Claude 做法 | 我們採用 |
|---|---|---|
| 子對話入口 | **不出側欄樹**——子 thread 以「卡片」內嵌在母對話訊息流下方（每張卡=一個小隊：名稱+狀態+進度勾選），點卡=全螢幕推入該 thread | ✅ 同構：母頻道內「小隊卡」（狀態燈+進度）→ 點擊推入子 thread（導航棧） |
| 返回導航 | 推入式（push navigation）：子 thread ← 返回母對話，iOS 原生手勢 | ✅（我們三層制本來就是抽屜+推入） |
| 成果預覽 | 「Claude 做的東西**開在聊天旁邊**而非蓋住聊天，要看細節再全螢幕」（2026-10-29 官方更新原話，iPad/iPhone Duo）；一般 iPhone=底部抽屜半屏預覽→上拉全螢幕 | ✅ 對齊我們 §8.5a：半屏預覽抽屜 + 全螢幕二段式 |
| 側邊聊天（/btw） | 手機上不出側窗——因為螢幕小，打斷成本低；直接在主線問 | ✅ 手機不做側窗（桌面限定）——簡化正確 |
| 跨對話彙總 | 「環境卡」（本地/雲端+遙控開關）、「context 卡」（用量+壓縮鈕）、「outputs 卡」（檔案清單）以卡片形式嵌在對話資訊頁 | ✅ 借「outputs 卡」概念→任務卡產出檔案清單（§8.6 已拍板）；環境卡/context 卡不借（後置） |
| 共享記憶 | Project instructions/memory 自動到每個子 thread——一處修正全體繼承 | ✅ 對齊我們的記憶體系（伴侶記憶本就跨對話） |
| 執行位置 | thread 可跑雲端或本地、可從手機遙控切換 | ✅ 我們天生更強：主機=自家 Mac/DGX，手機=遙控窗（零雲端依賴=主權優勢） |

**手機版總結**：Claude 手機端的核心聰明處＝「**樹狀結構藏進卡片**」——側欄樹是桌面隱喻，手機用「母對話內的小隊卡＋推入導航」表達同一棵樹。我們照抄這個原則。
