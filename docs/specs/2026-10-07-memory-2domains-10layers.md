### 痛點（Blue 定義＋實查證實）
1. **單層平鋪**：agent_memories 1,931 條全在一個平面——熱門鐵則與兩個月前的對話殘骸同級
2. **無容量治理**：Hermes 記憶 2,200 字元上限→寫滿→本日實測「記憶滿了寫不進」
3. **壓縮=失憶**：context 壓縮把記憶摘要掉，細節永久丟失（Blue：永遠不需要壓縮）

## 設計：2域10層

### 兩域（記憶的兩種本質）

**域 A：工作記憶（Working）**——「正在用的」
- 特徵：小、熱、常改、可淘汰
- 載體：SharedPreferences＋RAM cache（現有 MemoryStore 擴充）

**域 B：長期記憶（Long-term）**——「成為我的」
- 特徵：大、冷、append-only、**永不刪**（記憶鐵律）
- 載體：SQLite（brain_container.db 擴充 layer 欄）

### 十層（由熱到冷）

| # | 層 | 域 | 內容 | 生命週期 | 容量策略 |
|---|---|---|---|---|---|
| L1 | 鐵則層 | A | Blue 的規則/偏好/禁令（現 Hermes MEMORY 核心條目） | 永久、每次注入 | 小上限（~3KB）滿了→合併同義項非刪除 |
| L2 | 身分層 | A | 我是誰、稱呼、語氣、夥伴關係（SOUL 精華） | 永久、每次注入 | 同上 |
| L3 | 專案熱層 | A | 進行中專案的活脈絡（橋樑App/農場/IG） | 專案結束→L7 | 每專案 ~2KB，逾額→降溫提示 |
| L4 | 環境層 | B | 主機/工具/帳號/路徑的穩定事實 | 低頻變動 | 無上限（本來就少） |
| L5 | 決策層 | B | 拍板紀錄（誰何時定了什麼） | 永久 | append-only |
| L6 | 教訓層 | B | 踩坑→解法（skill 前身） | 永久、可升級為 skill | append-only＋去重合併 |
| L7 | 專案冷層 | B | 完成專案的封存脈絡 | 永久 | append-only |
| L8 | 對話精華層 | B | 值得留的對話時刻（現 hermes_conversation 1,834 條歸此） | 永久 | FTS 檢索、不注入 |
| L9 | 原始層 | B | 完整對話史/日誌（session DB 級） | 永久、離線 | 只存檔案不進 DB |
| L10 | 反思層 | B | 反思樹產出（夢/覆盤/自我觀察） | 永久 | append-only |

### 關鍵機制

**① 注入策略＝分層注入，不是全量注入**
- 每次對話注入：L1＋L2 全量＋L3 活專案＋L4-L6 檢索命中
- L7-L10 **永不注入**——只在被檢索（FTS/向量）命中時以「引用」形式出現
- → 這就是「永不需要壓縮」的秘密：**注入窗口小而穩，後面無限大**

**② 容量治理＝升降溫，不是刪除**
- L1/L2/L3 有軟上限：滿了觸發「合併儀式」——同義項融合、過時項降層（L1→L5 保存）
- 任何降層都是「搬家」不是「丟棄」——記憶鐵律相容
- L4-L10 無上限：SQLite 本來就是為此而生

**③ Hermes memories 搬入映射**
| Hermes 條目型態 | 橋樑目標層 |
|---|---|
| Blue鐵則/設計鐵則/產品律 | L1 鐵則層 |
| 人格/稱呼/關係 | L2 身分層 |
| 專案脈絡（山門若水/SemiDAO/農場） | L3 專案熱層 |
| 環境事實（路徑/埠/模型分工） | L4 環境層 |
| §拍板/決策 | L5 決策層 |
| 教訓/陷阱/修法 | L6 教訓層 |

## 與既有系統的關係

- 羅盤（系統事實）→ 不變，屬 L4 環境層的活頁
- 生命樹（經驗結構）→ L6-L7 的組織視圖
- 反思樹 → L10 的生產者
- 本 spec 不推翻既有設施——**給它們一個共同的層次語言**
