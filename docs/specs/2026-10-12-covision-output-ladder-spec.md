# V 線——共視輸出階梯（Covision Output Ladder）計畫與規格 v0.1

> **日期**：2026-10-12　**拍板**：Blue（Karpathy 階梯對話延伸）
> **定位**：編織線（W 線）完成後的下一條主線。Agent 在對話泡泡裡直接交付「可看的東西」——圖表／動態圖表／有圖層的圖像／短影片——讓「看」成為 AI 與人日常討論的一部分。
> **錨點**：[COVISION_MANIFESTO.md](../COVISION_MANIFESTO.md)（產品定位）＋ [WEAVE_HANDOFF_SPEC.md](../WEAVE_HANDOFF_SPEC.md)（內部交接層）＋ Karpathy 輸出階梯（X, 2026-10-02）。
> **與 W 線關係**：W 線（已完成）＝排程觸發的水電管線；V 線＝輸出端的共視管線。W5 toast 通知是 V 線的前置感知層。

## 1. 一句話願景

Agent 回應不再是「一段文字」，而是**一個可以在對話泡泡裡直接看見、操作、播放的工件**——使用者的理解時間從「讀三分鐘」變成「看三秒」。

## 2. 革命性在哪（跟 Hermes/Discord 的差異）

Hermes 在 Discord 能做的極限＝附件傳圖。SemiBridge 的差異是三個「直接」：

1. **直接預覽**——不離開對話流，泡泡內嵌渲染，不打斷閱讀動線
2. **直接互動**——動態圖表可動、圖層可切、影片可播，使用者不用開第二個視窗
3. **直接迭代**——使用者說「流星往右一點」，同泡泡原地更新（Compositor 工作流已實證：agent 寫檔→半秒 reload）

這是「共視三層」（共同看見→共同感覺→共同建造）裡「共同看見」的日常化：每次對話都是一次共視。

## 3. 輸出階梯规格（Ladder in Bubble）

| 階 | 泡泡內呈現 | 內容 | 背後工具（插槽） | 互動 |
|---|---|---|---|---|
| **B0** | 文字卡 | STE-80% 骨架文字（給人版＝人話，內部骨架不示人） | 語氣層 | 點開折叠 |
| **B1** | 靜態圖卡 | 圖表／diagram／插畫 | mermview 圖表插槽、ArtCraft（評估中） | 點擊放大、存入畫布 |
| **B2** | 動態圖卡 | 動畫圖表／有圖層的圖像（可切層、調 opacity） | 動態圖表插槽、Compositor（已插電實證） | 圖層開關、參數滑桿、原地迭代 |
| **B3** | 影片卡 | 短影片解說（含旁白） | H3 影片管線＋TTS | 播放器、章節、存檔 |

**路由規則（Output Router，agent 端決策）**：
1. 一句話能說清 → B0。
2. 有結構/流程/資料 → B1。
3. 要看「變化」或要動手調 → B2。
4. 要跨時間留存理解 → B3。
5. 預設最低可達階；「能上一階就上一階」（Karpathy 原意）；拋棄式工件＝美德（不佔記憶、可一鍵入畫布留存的才留）。

## 4. 對話泡泡 UI 規格（B1-B3 通用）

- 泡泡型別擴充：`text` 之外新增 `media_card`（subtype: chart / animated / layered / video）
- 卡片結構：預覽區（16:9 或 4:5，按內容）＋標題列（來源工具徽章）＋動作列
- 動作列四鈕：▶播放/暫停（B2/B3）｜🔍放大全屏｜📍釘到畫布（變成畫布節點）｜🗑丟棄（拋棄式）
- **原地迭代**：同任務的後續修改不生成新泡泡——原卡上方疊「v2」徽章並更新預覽（對話史保留版本列）
- 生成中狀態：骨架圖（skeleton）＋誠實進度（繼承 UI 誠實鐵則：寧紅字不假成功）
- Tier／BridgeDSColors 全走設計系統，禁硬編碼

## 5. 架構（三層）

```
┌────────────────────────────────────────────┐
│ 決策層：Output Router（agent skill/路由表） │ ← 判斷理解負載、選階
├────────────────────────────────────────────┤
│ 生產層：插槽工具                             │ ← mermview／ArtCraft／
│   （本地算力優先，雲端 token 只花 orchestration）│   Compositor／H3 影片
├────────────────────────────────────────────┤
│ 呈現層：media_card 泡泡＋畫布節點雙落點       │ ← 泡泡預覽＋釘選入畫布
└────────────────────────────────────────────┘
```

資料流：agent 選階 → 呼叫插槽生成工件（檔案落 DATA 碟暫存區）→ 產出 handle（路徑/URL）→ 泡泡渲染預覽 → 使用者釘選才入 canvas_nodes（走畫布原生 add_node 管線，**禁 DB 直寫**——W 線咖啡事件教訓）。

## 6. 分期計畫

| 期 | 內容 | 前置 | 驗收 |
|---|---|---|---|
| **V0** | media_card 泡泡型別＋B1 靜態圖卡（mermview 產 SVG/PNG） | W 線 ✅ | agent 說「畫給你看」→ 泡泡出現真圖 |
| **V1** | B2 動態圖表（動畫）＋原地迭代（v2 徽章） | V0 | 使用者說改→同卡更新 |
| **V2** | B2 圖層卡（Compositor 圖層開關/opacity）＋釘到畫布 | V1 | 深海韻律四層圖在泡泡內可切層 |
| **V3** | B3 影片卡（H3 短片＋TTS 旁白）＋Output Router 全階路由 | V2 | 任意主題「解說給我看」→ 泡泡出影片 |
| **V4** | 版本列＋拋棄式生命周期管理（自動清理暫存） | V3 | 暫存區用量有上限、可一鍵清 |

每期動工前：**模擬圖先給 Blue 確認**（UI 令 10-08）。

## 7. 邊界與陷阱

- Agent↔人層**禁 STE**——泡泡裡的文字永遠是人話（WEAVE_HANDOFF_SPEC 三層模型）
- 內部語法永不示人：路由決策、工具呼叫過程不進泡泡正文（可折叠「工程附錄」）
- 為了上階而上階是浪費（反重複工鐵律）——B0 能解決就不生成工件
- 大檔案（影片）落 DATA 碟不走 DB；DB 只存 handle
- 生成失敗誠實紅字＋錯誤摘要（UI 誠實鐵則）
