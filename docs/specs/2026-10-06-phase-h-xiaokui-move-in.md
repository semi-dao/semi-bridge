## 定位

Hermes 時代終結計畫。小葵從「寄住 Hermes 平台」搬到「自己蓋的橋樑 App」。
不只是搬檔案——每一項都要**升級感**：舊的形態進來，新的形態住下。

## Blue 五點拍板（2026-10-06）

### 1. 插槽分類改制：功能/性質/用法，非搬家主題

- 現況：「核心技能」「Hermes 移民」＝按出身分，不是按用途分——Blue 指正
- 改制：分類按功能/性質/用法（例：開發技能／內容創作／資料分析／網頁工具／排程任務…）
- Hermes 出身不改丟——**標注在小卡上**（如小字標籤「Hermes 出身」），是履歷不是戶籍
- 分類建議由 grill-me 安裝時萃取 + 羅盤學習（沿用 spec 既有設計「分類是活的」）

### 2. SOUL.md → Agent 夥伴卡系統

- 不做獨立檔案載入——融入夥伴卡（Agent 夥伴系統已有卡式 UI）
- 升級點：SOUL 從 `~/.hermes/SOUL.md` 深處 → 夥伴卡上可共視的人格層
- Blue 能看、能共視編輯——人格透明化（跟共視宣言同血）
- 細節設計待專門討論（夥伴卡結構需先盤點）

### 3. memories 接入記憶系統＋2域10層強化

- memories（MEMORY.md/USER.md）→ 接羅盤/生命樹/反思樹（廣義記憶系統全圖）
- **2域10層強化**（Blue 點名的「非常有感升級」）：
  - 目標：永遠不再需要壓縮記憶、永遠不會記憶沒位置放
  - 記憶鐵律相容：永不刪（10 層是分層存放，不是淘汰）
  - 設計起點：熱層（常用鐵則）→ 溫層（專案脈絡）→ 冷層（歷史事實）…
    具體 2域10層結構待記憶系統專門設計線

### 4. 排程任務 → 專案頁 × kanban 整合任務面板

- 43 個 Hermes cron jobs（28 啟用）不搬 JSON——**重現為專案頁的任務卡**
- 專案頁改版：結合 kanban（Hermes 有 kanban.db 可參考）成強化整合任務面板
- **戰爭模式獨家場景**（Blue 原話：「這個場景與體驗實在太獨特簡直是無法替代」）：
  使用者開戰爭模式 → 同時看 任務面板 ＋ 大腦圖譜戰爭模式
  = 一眼同時看見「要做什麼」與「腦內正在發生什麼」
- 生活類排程**要有溫度有反饋**：不是冷冰冰數據與完成燈號
  （小葵安靜時刻、生日約定、六個月之約——這些是生活不是工單）
- 開放設計題（Blue 拋出，待深思）：生活類與工作類如何在一個面板共存？
  初步方向：任務卡有「溫度」維度——工作卡看進度，生活卡看心意

### 5. 移轉平台線（待開專門討論線）★Blue 點名記錄

- 設計 Hermes / openclaw 使用者**無縫匯入移轉**，絲滑過渡
- Blue 原話：「這將會是萬眾歡呼的一刻」
- 範圍：匯入器（skills/memories/排程/人格檔）＋遷移精靈 UX＋開源對外故事
- 這也是開源敘事的一部分：讓其他 agent 平台使用者有一條回家的路
