# 橋樑氣氛設計語言 (Bridge Atmosphere Design Language)

> **狀態**：v0.1 草稿（2026-08-06 啟用）
> **角色**：Bridge LOGO 動畫、DAO 鉚釘瞬間、AI 共識提示、畫布粒子背景等所有「事件驅動視覺效果」的設計規範
> **生效範圍**：獨立於 `BridgeDSColors` token 層；只在氣氛層 z-index 內運作
> **不影響**：App 功能層 UI、字體級距、顏色 token 表、widget 邏輯
> **參考座標**：Active Theory（activetheory.net）的 WebGL 設計紀律
> **適用平台**：橋樑 App 桌面版（macOS / Windows / Linux）

> **📱 手機版刪除宣告（2026-08-10）**：
> - 手機版已正式宣告刪除，本氣氛設計語言專注於桌面版實作
> - 未來手機版將重新設計，可能簡化或調整氣氛效果以適應行動裝置性能限制
> - 行動版 GPU 預算將更低（≤ 1%）

## 1. 為什麼需要獨立文件

Bridge App 的視覺目前分兩層：

| 層級 | 範圍 | 文件 |
|---|---|---|
| **功能層** | 對話、畫布、表單、按鈕、字體、色塊 | `DESIGN.md` + `BRIDGE_TYPOGRAPHY_DESIGN_PRINCIPLES.md` + `BRIDGE_COLOR_BLOCK_DESIGN_GUIDE.md` |
| **氣氛層** | 開機 Splash、DAO 鉚釘瞬間、AI 思考、粒子背景 | **本文件** |

兩層的**紀律標準不同**：

- 功能層 → 對齊 Raycast + xAI 的「暗底低飽和、長時間使用不疲勞」
- 氣氛層 → 對齊 Active Theory 的「粒子宇宙、量子感、事件驅動」

兩層之間**永遠不會互相搶按鈕點擊、焦點、focus**。氣氛層只透過事件 bus 接收觸發，渲染時永遠在功能層之下（z-index 邏輯）。

## 2. 核心設計原則

### 2.1 五個從 Bridge Design Language 繼承的原則

| 原則 | 氣氛層的具體實踐 |
|---|---|
| **清醒** | 氣氛只在該出現的時候出現，結束就完全退出。**絕對沒有「永遠在動的全屏粒子」**。 |
| **貼近** | 氣氛層的 GPU 預算 ≤ 5%（桌面）、≤ 1%（行動版）。絕不讓風扇狂轉。 |
| **可感知** | 粒子、發光、軌跡 = 把抽象的「資料節點」「共識」「鉚釘」對人變可見。 |
| **有回應** | 氣氛是「對事件的回應」而不是「裝飾」。每次出現都有可指認的觸發源。 |
| **不斷線** | 氣氛層與功能層之間的事件通訊是冪等、可恢復、不打斷使用者流程的。 |

### 2.2 從 Active Theory 蒸餾的設計紀律

源自 activetheory.net 自己 Medium 文章「The Story of Technology Built at Active Theory」明確寫下的原則：

> "high CPU usage is actually the most likely culprit of a common negative symptom of WebGL experiences, **the annoying sound of fans spinning up to full speed**."

| 紀律 | 氣氛層對應行為 |
|---|---|
| 風扇不能狂轉 | GPU ≤ 5%、CPU ≤ 8%、記憶體峰值 < 200MB |
| 主執行緒不被佔用 | 粒子計算全在 Isolate / WebWorker / GPU shader |
| 跨平台單一 codebase | Flutter CustomPainter + fragment shader；iOS/Android/macOS 共用 |
| 視覺豐富但資源節制 | texture 解析度 ≤ 1024×1024；粒子數上限 4096 |
| 功能透明命名 | widget 名稱用具象功能命名（`SplineParticle`、`DaoSealBurst`），不是 `CoolAnimation2024` |

## 3. 視覺原語 (Atoms)

氣氛層最基本的可組合元素。所有「動畫」「視覺效果」都由這些原子組成。

### 3.1 粒子 (Particle)

```yaml
particle:
  shape: [spline | triangle | mesh | custom]   # 形狀
  size: 1-100px                                # 半徑
  count: 1-4096                                 # 數量上限
  spawn_rate: 0-200/sec                         # 生成速率
  lifetime_ms: 100-10000                        # 生命週期
  color: token                                  # 從 manifest 注入
  alpha_curve: [linear | ease-in | ease-out]   # 透明度變化
  motion:                                       # 移動方式
    type: [linear | spline | orbital | random-walk]
    speed: px/sec
    gravity: vector                             # 受力方向
```

### 3.2 軌跡 (Trail)

粒子移動時留下的視覺痕跡。呼應 Active Theory 的 `SplineParticleInstance` shader。

```yaml
trail:
  length: 1-50                                  # 軌跡長度（粒子數）
  decay: [linear | exponential]                  # 衰減方式
  blend_mode: [normal | soft-light | overlay]    # 混合模式
```

### 3.3 發光 (Glow)

```yaml
glow:
  radius: 5-200px
  intensity: 0-1.0
  color: token
  pulse:                                        # 脈動效果
    frequency_hz: 0-2.0
    amplitude: 0-1.0
```

### 3.4 中心點 (Central Point)

「共視」動作發生處的標記。**永遠在兩元素的中軸線上**。

```yaml
central_point:
  position: center                              # 鎖死：永遠在中心
  size: 1-20px
  shape: [dot | diamond | lotus | eye | custom]
  color: token
```

## 4. 事件分類 (Events)

氣氛層只在「事件發生」時觸發。事件由 Bridge App 的功能層發送，氣氛層只接收。

### 4.1 事件總覽

| 事件 | 觸發源 | 氣氛表現 | 持續時間 |
|---|---|---|---|
| `splash.startup` | App 啟動 | 兩個粒子從兩側飛向中心 → 中心點發光 → LOGO 鎖死 | 1.5 秒 |
| `dao.seal` | 三觀察者共識鉚釘一個事實 | 三道光束匯聚中心 → 中心爆發粒子 → 結界穩定 | 0.8 秒 |
| `ai.thinking` | Agent 正在思考 | 訊息氣泡周圍短暫粒子浮現 | 3 秒（或回覆完成） |
| `canvas.workflow.running` | 畫布工作流執行中 | 背景粒子**永遠不動**，只有「正在跑」的節點周圍發光 | 工作流期間 |
| `consensus.formed` | 共識達成 | 中心點發光一次，所有觀察者粒子向中心靠攏 | 1.2 秒 |
| `vector.completed` | 資料向量化完成 | 中央點向上擴散粒子雲 | 0.6 秒 |

### 4.2 事件觸發的數學鎖死

**所有「兩粒子飛向彼此」的動畫，必須以 SemiMaker 時刻的數學比例為時間基準。**

## 5. SemiMaker 時刻表

> **命名**：2026-08-06 由 使用者 命名
> **定義**：一天 24 小時內，時針與分針真實重疊的 21 個時刻
> **用途**：Bridge LOGO 動畫、DAO 鉚釘瞬間、AI 共識提示等所有「兩粒子飛向彼此」動畫的時間度量單位
> **數學性質**：
> - 重疊條件：分針角度 = 時針角度（兩條軌跡交會）
> - 速率比：分針 : 時針 = 12 : 1
> - 重疊間隔 = **720/11 分鐘 ≈ 65.4545 分鐘**（無理數循環小數）
> - 24 小時內次數 = **21 次**
>
> **🔒 鎖死層（永遠不變）**：
> - 21 這個數字本身
> - 每個時刻的時分秒
> - 720/11 這個無理數間隔
> - 正午 12:00:00.000（k=11）作為唯一完美對齊時刻
> - 「兩條獨立軌跡自然交會」的數學性質
>
> **這個「數」的邏輯本身可被常常拿來使用**，作為 Bridge 所有「兩元素共視」事件的時間度量單位。

### 5.2 數學鎖死事項

任何「兩粒子飛向彼此」的動畫必須遵守：

1. **時間基準 = 720/11 ≈ 65.4545... 的比例單位**  
   不能憑感覺定動畫時間。每段動畫的飛行時間 / 等待時間 / 結束時間都必須是這個無理數比例的倍數。

2. **正午 12:00:00.000（k=11）是唯一完美對齊時刻**  
   兩條軌跡完美回到 12 點。其他 20 次都在 1-11 之間某個刻度相遇。  
   **這個唯一性本身就是 LOGO 的「完美鉚釘」隱喻**。

3. **間隔是無理數循環小數**  
   永遠不會完美重複，但每次間隔的「比例」一樣。  
   **這就是「共識可以被重複製造，但每次都是獨立的觀察」的數學對應**。

4. **總數 21 次是固定的**  
   不是 22、不是 20、不是 24。**社群主題包無法改變這個數字**，就像無法改變「三觀察者」的數學下限。

5. **21 個時刻全部都必須被引用、不得選擇性使用**（2026-08-06 使用者 修正）  
   主題包不能「選用」某幾個時刻作為自己的品牌錨。  
   **「這個數的邏輯」可被常常拿來使用**——任何「兩元素共視」事件的時間基準都應該回到 720/11 這個無理數比，**但不能選擇性使用其中特定幾個時刻**。

### 5.3 三個層次的用法

#### 層次 1：Splash 動畫的時間軸（核心）

```
總長 1.5 秒（≈ 1.5 × 720/11 / 65.4545 = 16.5 個比例單位）

  0.000s — 0.500s   兩個粒子從左右兩側飛向彼此（速度 v₁）
  0.500s — 0.681s   兩個粒子停在「共識位置」（中心點兩側）
  0.681s — 1.022s   中心點發光擴散
  1.022s — 1.500s   LOGO 鎖死、粒子消散成光暈、進入 App

關鍵：v₁ : v₂ = 11 : 5（兩個粒子速度比 = 重疊數的奇偶關係）
```

#### 層次 2：主題包**不可**選擇「品牌時刻錨」（已修正）

> **2026-08-06 使用者 修正**：主題包**不能**從這 21 個時刻中選一個作為自己的「品牌時刻」。
>
> SemiMaker 時刻是 Bridge 的**時間度量單位**，是數學鎖死的。社群設計者**不可以**選擇性地使用某幾個時刻，也不能把某個時刻當作「品牌專屬」。
>
> **「這個數的邏輯」可以常常拿來使用**——意思是：
> - 任何主題包的任何動畫，只要涉及「兩元素交會」「共識形成」「觀察鉚釘」，**都可以（且應該）參考 720/11 這個無理數比**作為時間基準
> - 但**不可以用「自選錨點」這種方式**去改變或選擇特定時刻
>
> **真正的開放事項**只有這些（5 項，5 個維度）：
>
> | 可改 | 範圍 |
> |---|---|
> | 半圓的具體形狀 | 實心 / 鏤空 / 粒子雲 / 鑽石 / 蓮花瓣 / 羽毛 |
> | 半圓的相對距離 | 決定「動」的多強（緊貼 = 純靜態、拉開 = 強烈動感） |
> | 中心點的具體形狀 | 點 / 光 / 心 / 蓮花 / 眼睛 / 鑽石 |
> | 外圓框的形狀與粗細 | 圓 / 方形 / 橢圓 / 八角 + 1-10px |
> | 顏色、發光強度、粒子密度、背景氛圍 | 完全開放 |
>
> **至於動畫的「時間感」，必須回到 720/11 這個無理數比**。每段動畫的飛行時間 / 等待時間 / 結束時間都必須是這個比例的倍數。社群設計者**不能改動畫時長**，只能改形狀、顏色、氛圍。

#### 層次 3：永恆記錄（不可改變）

這 21 個時刻**永久刻進所有主題包的 `manifest.json`** 的 metadata 區，作為 Bridge 對「觀察的時間度量」的統一承諾——

**所有主題包都必須帶這份時刻表的引用**（不是「選一個」，是「全部帶著」），這是 Bridge 對「觀察的時間度量」的統一承諾。

## 6. LOGO 形狀規則（鎖死層）

semiDAO 的視覺記號由三個原子構成：

```
        ╭─────────────────╮
        │                 │
        │      ◐  ◑       │    ← 兩個半圓（觀察者 + 被觀察者）彼此面對
        │                 │
        │        ·        │    ← 中心點（共視這個動作發生的地方）
        │                 │
        ╰─────────────────╯
```

### 6.1 鎖死事項（5 條）

| 鎖死 | 原因 |
|---|---|
| 1. **半圓數量是 2** | 不是 1（單一觀察）、不是 3（會與「三觀察者」混淆）、不是 ∞ |
| 2. **兩個半圓必須彼此面對** | 「視」的本質。不可背對、不可同向、不可平行 |
| 3. **中心點必須存在**（即便隱藏） | 不論大小、位置永遠在兩半圓的中軸線上 |
| 4. **外圓框必須存在** | 「共」的世界邊界。可改形狀但不能沒有 |
| 5. **整體在三個尺度都成立** | 16×16 favicon / 1024 App icon / 任意尺寸 |

### 6.2 可改事項（社群設計者的「形狀之肉」）

| 可改 | 範圍 |
|---|---|
| 半圓的具體形狀 | 實心 / 鏤空 / 粒子雲 / 鑽石 / 蓮花瓣 / 羽毛 |
| 半圓的相對距離 | 決定「動」的多強（緊貼 = 純靜態、拉開 = 強烈動感） |
| 中心點的具體形狀 | 點 / 光 / 心 / 蓮花 / 眼睛 / 鑽石 |
| 外圓框的形狀與粗細 | 圓 / 方形 / 橢圓 / 八角 + 1-10px |
| 顏色、發光強度、粒子密度、背景氛圍 | 完全開放 |

## 8. 分層 Compositing 規則

氣氛層與功能層的 z-index 與事件通訊必須遵守：

```yaml
z_index_layers:
  - z=0:   功能層背景 (BridgeDSColors.canvas)
  - z=10:  功能層主體 (按鈕、對話、表單)
  - z=100: 氣氛層背景粒子 (永遠在最底層，僅在事件觸發時可見)
  - z=200: 氣氛層主效果 (鉚釘瞬間、Splash、AI 思考)
  - z=300: 系統通知層 (toast、alert)
  - z=999: Debug 覆蓋層

event_bus:
  direction: 功能層 → 氣氛層（單向）
  protocol: pub/sub via BridgeEventBus
  guarantee: at-most-once（氣氛效果丟掉不影響功能）
  idempotency: 每個事件有 UUID，氣氛層可偵測重複
```

**禁止事項**：

- 氣氛層**不可**向功能層發送任何訊息
- 氣氛層**不可**攔截滑鼠 / 觸控事件（永遠 `HitTestBehavior.translucent` 或 `deferToChild`）
- 氣氛層**不可**修改 BridgeDSColors token 值
- 氣氛層**不可**改變字體級距或顏色飽和度

## 9. 性能預算與降級策略

### 9.1 GPU / CPU 預算

| 平台 | GPU 上限 | CPU 上限 | 記憶體峰值 |
|---|---|---|---|
| macOS 桌面 | ≤ 5% | ≤ 8% | ≤ 200MB |
| iOS | ≤ 3% | ≤ 6% | ≤ 150MB |
| Android | ≤ 2% | ≤ 5% | ≤ 100MB |
| Web | ≤ 4% | ≤ 7% | ≤ 180MB |

**測量方式**：用 `flutter devtools` 的 Performance Overlay + Activity Monitor 的 GPU History。

### 9.2 自動降級策略

```
優先順序（由高到低）：
1. 完整粒子效果（預設，桌面版）
2. 簡化版粒子（粒子數量砍半、軌跡長度砍半）
3. 靜態發光（只用 glow，無粒子）
4. 純文字提示（中心點變成 "✓" 字符）
5. 完全關閉氣氛層（僅功能層）
```

降級觸發條件：
- GPU 使用率連續 5 秒 > 上限 → 降一級
- 溫度感測器 > 65°C（行動版）→ 直接降到第 3 級
- 電量 < 20%（行動版）→ 降到第 4 級
- 使用者手動在「外觀設定」關閉 → 降到第 5 級

## 附錄 A：數學驗算記錄

**SemiMaker 時刻表的推導**：

設 `t` 為從 00:00 起算的分鐘數：
- 時針角度 = `0.5t` (mod 360)
- 分針角度 = `6t` (mod 360)
- 重疊條件：`0.5t ≡ 6t (mod 360)` → `5.5t = 360k` → `t = 720k/11`

`k ∈ {1, 2, ..., 21}` → 24 小時內 21 次

**驗算（Python + Fraction）**：
```
#1  k=1  01:05:27.272   ✓
#11 k=11 12:00:00.000   ✓ (完美對齊)
#21 k=21 22:54:32.727   ✓ (最後一次)
間隔 = 720/11 = 65.454545... 分鐘  ✓
```
