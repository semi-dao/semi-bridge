# Bridge 統合設計語言（六源蒸餾）

> **狀態**：v1.0 · 2026-08-08
> **定位**：不是新的視覺模板；是 Bridge 對設計衝突的裁決規則。
> **上游母本**：[DESIGN.md](../DESIGN.md) 的五源融合 + Active Theory（activetheory.net）。
> **下游規則**：排版、色塊、Tier、氣氛、Theme Pack 都必須服從本文件。

## 0. 為什麼需要統合

Bridge 的來源不是單一設計系統：

- xAI 的清醒科技感
- Raycast 的長時間使用舒適度
- Stripe 的向量／資料可視化能力
- Figma 的即時回應感
- Miro 的無限畫布連續性

它們不能輪流當「皮膚」。如果一頁今天像 Raycast、下一頁像 Figma、畫布又像 Miro，使用者走過去會感到 App 在斷線。

**Bridge 的答案不是混搭，而是蒸餾。** 五個來源各自只保留一種不可取代的能力；所有 UI 共同服務一個核心承諾：

> **讓人與 AI 在同一個不斷線的空間中，把還沒有形狀的感覺、問題與決策，一步步共同看見。**

---

## 1. 六源 → 六種 Bridge 能力

| 來源 | Bridge 保留的能力 | 不等於什麼 | 必須出現在哪裡 |
|---|---|---|---|
| **xAI** | **清醒（Clear）**：低噪音、技術感、資訊可判讀 | 不是冷漠的黑色介面 | 預設背景、系統狀態、長文閱讀 |
| **Raycast** | **貼近（Close）**：表面層級、色彩節制、長時間不疲勞 | 不是滿畫面的卡片與彩色 badge | 表單、清單、控制面板、日常工作頁 |
| **Stripe** | **可推演（Legible Complexity）**：讓資料、關聯、過程看得見 | 不是裝飾性漸層或炫耀性粒子 | 大腦、圖譜、模型、分析、交易與關係資料 |
| **Figma** | **有回應（Responsive）**：每一次操作都有立即而可理解的回饋 | 不是所有元件都彈跳 | 按鈕、拖曳、選取、完成、錯誤與過場 |
| **Miro** | **不斷線（Continuous）**：空間、上下文、路徑連續存在 | 不是無邊際地堆內容 | Canvas、跨頁導航、子工作流、歷史與縮放 |
| **Active Theory** | **可沉浸（Immersive）**：事件發生時，整個畫面成為一個有情緒的場域 | 不是永遠在動的裝飾背景 | Splash、共識達成、鉚釘瞬間、AI 思考軌跡、重大完成 |

### 1.1 Bridge 的第七個結果：共視（Co-seeing）

> 📌 **共視已升格為橋樑的產品定位錨點**——見 [共視宣言](COVISION_MANIFESTO.md)（2026-08-09 Blue 指示）

六種能力不是平行的；它們合起來才產生 Bridge 獨有的結果：**共視**。

- 人看見的是工作、關係與決策。
- AI 看見的是資料、狀態、下一條可能路徑。
- 畫面把兩者放在同一個可回應、可延續的場域。

因此，任何設計若只「好看」但不能幫人與 AI 共同看見，就不是 Bridge 設計。

## 2. 固定的層次，而非固定的風格

Bridge UI 永遠先分成三層；五源能力在正確層出現，不能搶位。

```text
Layer A — 功能骨架（預設安靜）
  xAI 清醒 + Raycast 貼近
  文字、表單、清單、操作、狀態：必須可讀、可用、可長時間停留。

Layer B — 關係與推演（只在需要理解複雜時出現）
  Stripe 可推演 + Miro 不斷線
  節點、向量、圖譜、交易、畫布：要讓關係可見，但不蓋過功能。

Layer C — 事件氣氛（只在可指認的事件發生時出現）
  Figma 有回應 + Active Theory 可沉浸
  收束、完成、共識、思考、啟動：短暫出現、留下意義、自然退場。
```

**禁止反轉層次**：不能讓 Layer C 的粒子／光暈，永久壓在 Layer A 的文字與操作之上。

---

## 3. 衝突裁決順序

當五種能力互相衝突時，使用以下順序，不憑喜好猜：

1. **功能可用性**：能看懂、能操作、能復原，永遠第一。
2. **連續性**：使用者不能失去「我在哪、剛剛做了什麼、下一步去哪」。
3. **資訊可推演性**：複雜資料必須幫助理解，不可只做裝飾。
4. **回應性**：每個可操作控制項都必須有對應結果。
5. **沉浸性**：重要事件值得被放大成為場域，但必須有明確的進場和退場。
6. **氣氛與驚喜**：只在前五項成立後，才有資格出現。

### 3.1 快速裁決例子

| 衝突 | 正確裁決 |
|---|---|
| 粒子很美，但蓋住文字／造成閱讀疲勞 | 移除或降級粒子；功能層優先 |
| 動畫有趣，但按下後使用者不知道是否完成 | 補明確狀態；回應優先於趣味 |
| 畫布很大，但使用者找不到回到工作流的位置 | 補位置／路徑；連續性優先於無限感 |
| 色彩很豐富，但看不出成功、危險、選取 | 回到語意 token；資料可讀優先於裝飾 |
| Logo prototype 能表達收束，但形狀尚未定稿 | 保留動態語意，不把 prototype 宣稱成品牌 Logo |
| 沉浸式粒子場景很震撼，但使用者正在填表單 | 移除或降級為被動背景；功能層優先於沉浸感 |
| AI 思考的粒子軌跡很美，但持續超過 10 秒讓人焦慮 | 加退場時間或明確進度文字；回應性優先於沉浸感 |

## 4. 元件設計前的六問

新增任何頁面、卡片、控制項或動態前，先回答：

1. **清醒**：使用者一眼知道這是什麼、目前狀態是什麼嗎？
2. **貼近**：使用二十分鐘後，文字、對比與色塊仍舒服嗎？
3. **可推演**：如果有複雜資料，畫面是否真的讓關係更清楚？
4. **有回應**：每個看似可按的東西，是否有真實且可見的結果？
5. **不斷線**：從這裡離開、回來、放大或切換，使用者還知道自己在哪嗎？
6. **可沉浸**：如果有視覺效果，它是否只在重要事件發生時出現、結束後自然退場？

其中任一題答案為「否」，不得用更強的視覺特效掩蓋它。

## 6. 現階段設計決策

- 目前 Phase 1.2 的 atmosphere showcase **只驗收事件是否被可靠觸發**；不以粒子內容、Logo 形狀或完整宇宙觀作為本階段驗收。
- Splash 的雙元素收束是**動態語意 prototype**，不是正式 Bridge Logo。
- 正式 Logo 必須另開設計蒸餾：形狀、比例、負空間、16×16 到 App icon 的辨識度，以及靜止／收束兩種狀態。
- Phase 1.3 再將事件語意落實為量子平行宇宙的粒子語言；不可為了「看起來很動」而破壞 Layer A 功能骨架。

## 7. Active Theory 蒸餾矩陣（v1.0 新增）

> 「Active Theory treats the web like a medium, not a canvas. It's a studio that designs behavior, not just screens.」

| 維度 | Active Theory 的特徵 | Bridge 要留下什麼 | Bridge 明確不要 |
|---|---|---|---|
| **視覺核心** | 深色粒子宇宙、生物冷光、色彩繞射環 | 深色背景中的量子粒子——只在事件觸發時出現 | 永遠在動的全屏粒子牆 |
| **技術紀律** | Hydra 框架、GPU 預算嚴格、效能優先 | GPU ≤ 5%、CPU ≤ 8%、記憶體 < 200MB | 為了視覺犧牲流暢度 |
| **敘事方式** | 滾動驅動的世界切換、環境是故事的一部分 | 重大事件（共識、鉚釘、AI 啟動）有完整的視覺敘事 | 把日常工作變成動畫 |
| **跨平台** | 同一框架 → web、native、VR、安裝 | Flutter CustomPainter + shader 跨平台 | 為每個平台寫不同的視覺層 |
| **AI 整合** | AI 驅動的站內導航 | AI 思考過程可視化——不是裝飾，是真實的思考軌跡 | 用 AI 做純裝飾文字 |
| **情緒設計** | 整個畫面有情緒——不是 UI 有情緒，是場域有情緒 | Bridge 的重要瞬間（門打開、水流匯入、橋建成）有情緒 | 讓每個按鈕都「有情緒」 |

### 7.1 Active Theory 如何與其他五源共存

Active Theory 的「可沉浸」**永遠住在 Layer C**。它不會：

- 搶 Layer A 的清醒（xAI/Raycast 的功能骨架優先）
- 干擾 Layer B 的推演（Stripe/Miro 的資料可見性優先）
- 取代 Figma 的回應性（每個操作仍需有明確回饋）

它只做一件事：**在重要事件發生的那一刻，讓整個畫面成為一個有情緒的場域**。

### 7.2 什麼是「重要事件」

在 Bridge App 中，值得觸發沉浸層的事件：

| 事件 | 沉浸層行為 |
|---|---|
| App 啟動（Splash） | 雙元素收束——Bridge Logo 動態生成 |
| 門打開（Transurfing） | 短暫的開門視覺——空間感擴張後收束 |
| 水流匯入（完成） | 水流結束的匯流動畫——成果落地 |
| 橋建成（跨水流連結） | 兩條水流之間的連接光軌 |
| AI 共識達成 | 思考軌跡凝聚成一個結論點 |
| 鉚釘瞬間（DAO） | 上鏈存證的封印動畫 |

**不值得觸發沉浸層的事**：一般訊息送出、按按鈕、切換頁面、滾動列表。
