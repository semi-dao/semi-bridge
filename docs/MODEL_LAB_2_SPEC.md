## 核心隱喻

Model Lab 2.0 = **Semi 的健檢中心**。每個器官（記憶/直覺/小腦/前額葉）都有現役者；健檢中心負責：盤點現役 → 追蹤候選 → 體檢 → 報告 → 換役（或說明為什麼還不能換）。

## 五大功能

### ① 器官檔案館（Installed Organ Registry）— Blue 10-10 需求
系統主動辨識使用者安裝的各類模型，按**器官級距與種類**建檔：
- 掃描來源：HF cache（`~/.cache/huggingface/hub`）、llama.cpp models 目錄、App 容器（flutter_gemma 等）、LM Studio 目錄（可選）
- 每個模型建檔：`{器官候選類別, 參數量, context, 量化別, 授權, 安裝路徑, 首次發現日}`
- 類別判定法：模型 card 關鍵字（embedding/decision/generative/mmproj）＋ pipeline_tag＋使用者覆寫
- **現役標記**：哪個模型正在哪個器官上班（對接 local_model_catalog_service 既有資料）

### ② 候選人偵察（Candidate Scout）— 每週 HF 掃描
- 按**現役器官的類別**掃 HF 新發布（同類替換候選），非亂槍打鳥
- 過濾器：授權（Apache/MIT/Gemma 級）、參數量上限（按硬體 profile）、下載數/星數門檻
- 產出：「本週新候選」清單，附與現役的規格對照

### ③ 標準題庫體檢（Benchmark Harness）
- 題庫：`test/semi/fixture_s0_20cases.json`（S0 立的 20 題標準卷）＋按器官擴充子卷
- 方法沿用 S0 實證流程：embedding 類走近鄰法、decision 類走 typed questions
- 指標：正確率 / Brier（校準）/ 延遲（p50/p95）/ 記憶體
- **同卷同法可比**：報告自動與現役並列（EG2 vs 300M 的對照表就是原型）

### ④ 支援缺口追蹤（Gap Tracker）— Blue 10-10 需求
「體檢過關但通道不支援」的狀態要有名字、有下一步：
- 追蹤目標：llama.cpp release notes（`gemma-embedding2` 類架構支援）、transformers 版本、TFLite 轉換器
- 每週檢查 → 缺口解除時自動觸發通知：**「候選人 X 的通道已開通，可以進行第二次體檢」**
- 卡片狀態機：`已發現 → 已下載 → 體檢中 → 過關/未過關 → 通道等待中 → 可採用 → 已換役`
- 使用者任何時刻看卡片都知道：現在在哪一步、卡在哪、下一步是什麼（**過程不失去追蹤與應變**）

### ⑤ 換役與通知（Adopt & Notify）— Blue 10-10 需求
- **通知通道**（新候選出現/缺口解除/體檢完成）：
  - App 內：能力中心/模型實驗室卡片 badge＋首頁提醒
  - 系統層：App 通知（macOS notification）——重大事件（缺口解除、體檢過關）
  - Cron 層：每週掃描結果摘要推 Discord（管理者視角）
- **一鍵換役**：沿用既有「採用為現役」流程，但加**前置檢查**：體檢過關＋通道支援＋回滾方案（現役模型檔不刪，換役可逆）
