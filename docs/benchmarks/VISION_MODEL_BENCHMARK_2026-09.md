# 本地視覺模型盲測報告（2026-09）

> 背景：Covision Bridge 的照片索引（嵌入管線）依賴本地視覺模型描述照片。開源世界模型更新快，我們用「使用者自己的照片盲測」來做選型——這份報告就是第一次完整閉環的記錄。

## 測試方法

- **素材**：20 張農場真實照片（辣椒採收、鹿角蕨、陽台現況紀錄……），每張附 hint 關鍵詞
- **盲測**：模型對照片生成描述 → 判分腳本比對 hint 關鍵詞是否命中
- **指標**：命中率（品質）、秒/張（速度）、RAM 佔用
- **腳本**：`vision_bench.py`（可重演）

## 結果

| 模型 | 命中率 | 速度 | RAM | 定位 |
|---|---|---|---|---|
| **Gemma 4 12B** (Q4_K_M) | **19/20 = 95%** | ~104s/張 | 5.8GB | 🏆 品質首選 |
| Gemma 4 E4B (Q4_K_M) | 17/20 = 85% | ~47s/張 | 5.0GB | ⚡ 速度首選 |

- 12B 唯一 miss（第 11 張辣椒特寫）：描述其實有寫到辣椒，但判分詞沒中——**判分腳本邊角案例，非模型問題**
- 12B 是 thinking 模型：`max_tokens` 需 ≥1500（1024 以下推理段燒光 token 會空回應）

## 決策

**12B 登基為現役預設**（品質優先，95% vs 85%）；E4B 保留為一鍵切換的速度選項（照片批次量大時用）。

切換走 App UI 按鈕（系統 → 模型 → 設為現役），不走 CLI——這是產品路徑。

## 16GB 機器注意事項

- 12B（7.1GB 檔案）context 必須 ≤4096：App 的 Swift 層會依模型大小自動調整（32768 會 OOM 觸發 Jetsam）
- 不可同時跑 12B + E4B（雙 llama-server 必 OOM）

歡迎 PR 新模型進 `models/recommended-models.json`——附上同方法盲測數據即可。評測方法完全開源，跑你自己的照片更有意義。

## 附錄：量產線上學到的事（2026-09-29/30 生產環境實錄）

12B 登基後在每日生產（照片索引嵌入）跑了一週，補充實錄：

- **批次推論自殺**：12B 在連續批次（105s/張 × 20 張量級）偶發進程自殺（一週 4 次）——單張對話推論零事故。App 對策：引擎級看門狗（health poll + 自動復活 + 嘗試節流），詳見 repo 架構文件。
- **16GB 王朝紀律**：12B 主線 + E4B 快測不可同時跑；App 的「快渢 B' 方案」會自動停主線→獨佔 GPU→測完復活。
- **換模型 = 改一個 json**：`models/recommended-models.json` 列量化檔與 mmproj 配對——換新模型只要加一筆，App UI 自動出現選項。
- **thinking 模型的 max_tokens**：≥1500（推理段會吃掉配額，低於此值空回應）。
