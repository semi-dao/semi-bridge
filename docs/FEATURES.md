# Semi Bridge 功能說明——背景系統篇（Background Systems）

> 這些功能都源自真實事故：2026 年 9 月底，使用者一句「電腦很遲鈍連打字都難」
> 引發兩天偵查，挖出七座金礦。本文件是這些器官的**使用者視角說明**——
> 你不需要知道程式碼，只需要知道它們為你做了什麼。

## 🔄 系統活動中心（System Activity Center）

**問題**：背景任務（檔案掃描、向量嵌入、模型服務）都在默默跑，
但「默默」等於「看不見」——電腦變慢時，你不知道它在忙什麼還是壞了。

**現在**：系統頁頂部有一張活動卡。任何背景工作進行中，它會顯示：
- 任務名（如「自動檔案巡邏」「檔案嵌入」）
- 進度百分比與當前處理的檔案
- 完成後保留 5 分鐘供回看，然後安靜退場

**設計原則**：忙碌必可見，安靜即隱形。沒有任務時不佔任何畫面。

## ⏸ 溫和暫停（Gentle Pause）

每個進行中的任務都有 ⏸ 按鈕。按下去：

- 任務**不會**被腰斬——它會做完當前這一筆，然後在邊界優雅停住
- 你繼續用電腦（GPU/CPU 讓給你）
- 按 ▶ 繼續，從停住的地方無縫接手，**零重做**

這是「使用者意志神聖」的實踐：你的機器你優先，背景工作會等。

## 🌲 樹指紋快取（Tree Fingerprint Cache）

**問題**：每次重啟 App，檔案巡邏都要重掃全部資料夾（外接碟幾千個檔案），
CPU 燒一小時、風扇狂轉——但檔案根本沒變。

**現在**：每個資料夾的「樹指紋」（檔案結構摘要）存在資料庫。
重啟時先比對指紋：**沒變就整輪跳過**。實測從 80 分鐘降到秒級。

## 🧠 大腦自動復活（Brain Auto-Revival）

**問題**：本地模型引擎（llama-server）偶爾無聲死亡——UI 還顯示「運行中」，
但大腦其實已經不在了。你不發現，它就死一整晚。

**現在**：引擎級看門狗每 30 秒健康檢查（與模型型號無關——換任何
開源 GGUF 模型都受保護）。連續兩次無回應即判定死亡，自動重啟引擎。
防呆設計：重啟節流（10 分鐘最多試一次），不會變成重啟風暴。

## ⚡ 快指紋嵌入過濾（Fast Fingerprint Filter）

**問題**：判斷「檔案內容有沒有變」需要讀整個檔案算雜湊——
幾千個檔案就是幾十 GB 的讀取，就算檔案根本沒動。

**現在**：先比對檔案的「快指紋」（大小＋修改時間，毫秒級）：
一致＝內容沒變，直接跳過；不一致才讀檔案細算。**零讀檔擋掉 99% 的無效工作。**

## 🔒 嵌入狀態機（Embed Source State Machine）

向量資料庫的每筆資產有嵌入來源標記。`identity`（身份嵌入）是**終態**——
資料庫層強制不可逆轉（任何代碼想改回去，資料庫直接拒絕）。
這終結了一個反覆發生的慘案：兩個嵌入任務互相覆蓋，同一批檔案每天重做。

## 🧪 模型實驗室（Model Lab）

想在幾個本地視覺模型之間選型？實驗室讓你：
1. **快測**（3-5 張）：自動讓主引擎休眠→獨佔 GPU 測新模型→自動復活
2. **全測**（20 張）：快測成績好再問你要不要跑全測
3. **採用**：一鍵設為現役

全程 UI 按鈕，不碰 CLI。盲測方法與腳本見 [benchmarks/](benchmarks/VISION_MODEL_BENCHMARK_2026-09.md)。
