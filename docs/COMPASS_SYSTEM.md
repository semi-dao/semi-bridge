## 1. 一句話

**人寫「為什麼」，機器保證「是什麼」，羅盤是唯一真相源。**

App 的每一個器官、每一條規則、每一個踩過的坑，對人和 Agent 都是同一份、
永遠最新、誠實標記的活地圖。它是人機兩個平行宇宙握手的地方。

## 2. 病根：沒有羅盤的世界

| 現況 | 問題 |
|---|---|
| 架構地圖（markdown）人工維護 | 行號、檔案、陷阱隨版本漂移；地圖過期 = 系統對 Agent 說謊 |
| 更新靠紀律（「改完必須同步更新」） | 人會忘、Agent 會忘 |
| 只有開發者看得懂 | 使用者看不到 App 的身體；Agent 自我修改時使用者無從知情 |
| 規則住在程式碼常數與註解裡 | 改一條規則 = 改 code + 重 build + 改文件，三處同步遲早漂移 |

實證（2026-09-17 對 `causal_ledger.db` 353 筆工具呼叫的驗屍）：

- Agent 主動查羅盤次數：**0** —— 不是不乖，是沒有觸發機制
- 器官規則覆蓋率：**9/43** —— 34 個器官裸奔
- 直接代價：79 次 `read_source_file` 蠻力考古 = 羅盤缺藥的帳單

**結論：缺的不是地圖，是三件事——藥箱（內容）、上膛（檢索）、出診（觸發）。**

## 3. 核心設計：三層所有權

羅盤上每個器官（organ）= 一張卡片。卡片分三層，**各有所主、互不越權**：

| 層 | 內容 | 擁有者 | 誰可改 |
|---|---|---|---|
| **事實層** | 檔案路徑、依賴關係、健康狀態、誕生時間、MCP 端點、工具清單 | 系統自動採集 | 只有自動採集器（harvest）可寫；人與 Agent 都不能手改——保證「是什麼」永遠是真的 |
| **意義層** | 暱稱、白話說明、重要性 ★1-5、注意事項 | 人類 | 人自由改；Agent 可讀、可建議、不可靜默覆寫 |
| **規則層** | 顯示規則、門檻、模式係數——一條規則一張卡 | 共治 | 人可改；Agent 可建議；上線生效需人按「套用」 |

**忠實呈現原則**：每個欄位都帶 `(來源, 時間)` 標記——
`自動採集 · 09-06 14:00` / `Blue · 09-06 15:20` / `Agent · 09-06 16:00`。
人和 Agent 看到的是同一份，且都知道每個字是誰寫的。
**沒有匿名真相，沒有無主修改。**

規則層三原則：

1. **唯一寫手**：規則參數的唯一權威 = 羅盤 store；渲染端只讀不寫
2. **規則卡必帶「為什麼」**：強制欄位「這條規則解決什麼問題」，防止規則變成無主數字
3. **退役規則不刪除**：停用的規則卡轉「退役」狀態保留——未來 Agent 想復活舊寫法時，羅盤會告訴它「這條路曾經被誰、為什麼封掉」

過期誠實標記：事實層錨點採集驗證失敗（檔案搬了、類別改名了）→ 卡片轉琥珀色
「⚠️ 待重新驗證」。**絕不靜默刪除、絕不假裝新鮮。**

## 4. 軍醫三件套：從圖書館到隨隊軍醫

羅盤 v1 是圖書館——資料在，但 Agent 不會主動去翻。v2 補上**軍醫**（compass_medic）：

```
┌─────────────────────────────────────────────────┐
│  藥箱（Content）   常見傷的藥預先備齊            │
│  出診（Trigger）   動手前藥自動出現在眼前        │
│  長藥（Growth）    治好的傷自動變成新藥          │
└─────────────────────────────────────────────────┘
```

### 4.1 三個自動出診點（掛咽喉點，不靠 Agent 自覺）

| 觸發點 | 時機 | 動作 |
|---|---|---|
| **動手前** | 高風險工具（patch_source_file / canvas_add_node / run_terminal…）執行前 | 自動 compass_seek，命中卡片注入該輪 context（fail-open） |
| **撞牆時** | 同工具連續失敗 ≥2 次 | 自動送該工具的藥，附在下一次錯誤回報裡 |
| **開工時** | AgentLoop 冷啟動 | 注入器官地圖摘要卡（~250 tokens 瘦身版） |

### 4.2 傷口自癒循環（Growth）

```
工具失敗 → 自動立案【pending·傷口立案】坑卡
        → 同工具後續成功
        → 自動草擬藥方替換 pending 卡：症狀 → 病根 → 藥方 → 執行機制 → 出處
        → 供 compass_seek 檢索，未來同款傷一發命中
```

真實案例（本 repo 的 v0.4.0 LightUp 戰役入庫藥方）：

- 沙盒 App 內 `screencapture` 靜默失敗（TCC 無條目、外部 binary 被擋）
  → 病根：沙盒禁 exec 外部 binary 的螢幕擷取繼承
  → 藥方：App 內截圖一律 `app_look` / `app_view`（視網膜）
- Dart `ContentType.json` 預設 latin-1，寫中文 body 必炸
  → 藥方：`ContentType('application', 'json', charset: 'utf-8')`

### 4.3 紀律

每輪最多 3 張卡注入、fail-open 必留錯誤痕跡、注入計入 token 帳（BudgetLedger）。
**軍醫是隨隊的，不是主角——它不接管，只出診。**

## 5. 資料模型

`compass_store.db`（SQLite，與 App 資料同住 Application Support）：

| 表 | 內容 | 寫手 |
|---|---|---|
| `compass_organs` | 器官卡：id、系統群、名稱、事實 JSON、錨點健康 | harvest 唯寫 |
| `compass_rules` | 規則卡：歸屬器官、白話描述、為什麼、參數 JSON、狀態 | 共治（人套用生效） |
| `compass_pitfalls` | 坑卡：症狀 → 病根 → 藥方（含 pending 立案形態） | 自癒系統 + 人 |
| `compass_surgeries` | 手術記錄：誰、何時、對哪個器官、做了什麼 | _bump 自動記 |
| `compass_meta` | 版本、意圖索引（intent_index——Agent 檢索用口語關鍵詞地圖） | 系統 |

器官按系統群分組：對話、畫布、大腦、向量、專案、夥伴、服務群、肢體、協作系統。
種子清單見 `lib/services/compass/compass_seed.dart`（冪等 INSERT OR IGNORE，
事實層由 harvest 持續更新）。

## 6. 人機共視的雙向道

這是羅盤不同於任何「agent 記憶體」「知識庫」產品的本質差異：

**向人類**：頂部功能列「羅盤」頁——使用者親眼看見 App 有哪些器官、
每個器官健康嗎、上次誰改的、哪些規則正在生效。App 長出新器官的那一刻，
羅盤自動多一張卡：名稱、誕生時間、誰種的、狀態。**不需要 Agent 匯報。**

**向 Agent**：`compass_seek` 工具 + 意圖索引——Agent 用口語症狀查藥
（「改檔 patch 原始碼」「畫布 節點 空殼」），命中卡片注入 context。
羅盤 = Agent 的本體感（proprioception）。**沒有它的 Agent 是閉著眼睛動手術的醫生。**

**雙向握手**：

- 場景 A：使用者在「對話」器官標重要性 ★5 加註「改版面前先跟我討論」→
  三天後 Agent 要重構 UI，動手前讀羅盤 → 看到人類註記 → 降級為提案模式。
  **人伸出的手，第一次被機器握住。**
- 場景 B：Agent 長出新器官 → 羅盤自動多卡 → 使用者親眼看見。
  **機器伸出的手，人第一次即時握住，不是事後聽轉述。**

## 8. 設計哲學索引

- 三層所有權：事實自動／意義人寫／規則共治——**各有所主，互不越權**
- 誠實鐵則：過期標琥珀、退役不刪除、fail-open 留痕跡——**寧紅字不假成功**
- 咽喉點覆蓋：藥放在 Agent 一定會經過的地方，不是均勻撒
- 治癒系統不靠 Agent 自覺：出診是自動的，長藥是自動的
- 唯一真相源：與 v0.4.0 LightUp 的 MCP 工具清單同哲學——兩份清單 = 遲早漂移
