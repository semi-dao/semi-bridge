# 編織線交接規格——STE-80% 內部通訊協定 v1.0

> **定位**：Agent↔程式／Agent↔Agent 的縫隙層通訊規格（編織線任務專用）。
> **來源**：Karpathy 輸出階梯（X, 2026-10-02）＋ ASD-STE100 精神取 80%。Blue 拍板 2026-10-12。
> **不適用**：機器↔機器層（JSON/schema/API——已有規格，套 STE 反而降級）；Agent↔人層（UI/對話——真人話＋溫度，禁 STE）。

---

## 0. 三層通訊模型（先記住你在哪層）

```
        橋樑 App 內部通訊三層
┌─────────────────────────────────────┐
│ 機器↔機器   JSON / schema / API     │ ← 已有 schema，禁套 STE
│            （事件總線、MCP、埠真相源）│
├─────────────────────────────────────┤
│ Agent↔程式  任務卡 / 器官指令 / brief │ ← ★ 本規格管這層
│            （編織線的縫隙層）         │
├─────────────────────────────────────┤
│ Agent↔人    UI / 對話 / 報告         │ ← 禁 STE，真人話＋溫度
└─────────────────────────────────────┘
```

## 1. 六條寫作規則（STE-80% 核心條款）

| # | 規則 | 錯誤示範 | 正確示範 |
|---|---|---|---|
| R1 | **一句一動作**。禁一句話含兩個指令。 | 「打開畫布並匯入節點然後存檔」 | 「1. 開畫布。2. 匯入節點。3. 存檔。」 |
| R2 | **動詞統一**。同一動作全程用同一個詞，禁換同義詞。 | 開頭說「匯入」結尾說「載入」 | 全文皆「匯入」 |
| R2a | 動詞先註冊：文件開頭的動詞表列全部會用到的動作詞（開啟/寫入/驗證/回報），正文只用表內動詞。 | 正文出現表外動詞「搞一下」 | 動詞表：開啟、寫入、驗證、回報。正文只用這四個。 |
| R3 | **名詞先註冊再使用**。第一次出現給全名＋ID，之後用簡稱。 | 「把那個檔案修好」 | 「`schedule_registry.dart`（下稱 registry 檔）。修 registry 檔。」 |
| R4 | **禁歧義代名詞**。「它/這個/那個」必須能唯一解析。 | 「調高它的優先級」——它=誰？ | 「調高任務卡的優先級。」 |
| R4a | 禁省略主語當主語是跨段落引用。跨段引用一律重述名詞（R3 簡稱）。 | 上段講完 A 和 B，下段「把結果存檔」——誰的結果？ | 「把 B 的結果存檔。」 |
| R4b | 指令含否定時禁縮寫。否定詞加粗或獨立成句。 | 「別忘了跑測試」 | 「跑測試。**不可**跳過測試。」 |
| R5 | **數字必帶單位與來源**。 | 「延遲改善很多」 | 「延遲從 420ms 降到 180ms。來源：chrome tracer, run42。」 |
| R6 | **宣稱必附證據 handle**。沒有證據 = 明說「未驗證」。 | 「修好了」 | 「修好了。證據：`flutter analyze` 0 error, run42。」 |

## 2. 任務卡 brief 標準格式（交接模板）

每張編織線任務卡的交接欄位，照這個骨架填：

```
【任務】一句話目標（≤20字）
【動詞表】本文會用到的動作詞（通常 3-6 個）
【名詞註冊】檔案/類別/ID → 簡稱對照
【上下文】上一棒是谁、上一棒做到哪（證據 handle）
【步驟】編號清單，一步一句一動作
【驗收】可機器檢查的條件（指令＋期望輸出）
【證據】實際輸出 handle（路徑/exit code/截圖）
【邊界】禁碰的檔案/路徑（如：不碰主程式 DB）
```

## 3. 執行史病歷格式（W4 排隊卡失敗記錄）

```
【時間】ISO 8601
【症狀】Blue 白話原話（保留，不翻譯）
【根因】一句話＋指向檔案:行號
【修法】commit hash＋改了什麼
【驗證】指令＋實際輸出
```

## 4. 陷阱

- STE 只管骨架不管溫度——給 Blue 的報告仍是真人話（文風期待不變）。
- 內部語法永不示人：這份規格的產出在 UI 上永遠渲染成人話。
- 機器對機器層禁套用（已有 schema）。
- 為了上階而上階是浪費（反重複工鐵律）。

## 5. 與既有體系的關係

- `karpathy-output-ladder` skill（Hermes 端）管**路由**：選哪階輸出格式。
- 本規格管**縫隙層格式**：Agent↔程式交接怎麼寫才不誤讀。兩者互補。
- 對應 Blue 既有原則「spec 禁歧義，寫到不可誤讀＋回歸測試鎖死」——本規格是該原則的可執行格式。
