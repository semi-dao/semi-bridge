# Domain Modeling — 共享語言的紀律

專案最大的隱形成本：同一個詞、每個人腦中畫面不同。
領域模型 = 把「我們說的話」變成單一真相源。

**主動**的紀律（跟「讀一下 CONTEXT.md」的差別——被動讀是一行習慣，
主動建模是「正在改模型」時用的）：挑戰術語、發明邊界情境、
**當場**把結晶的定義寫下來。

## 檔案結構

```
/
├── GLOSSARY.md          # 詞彙表（唯一內容：術語→定義，零實作細節）
└── docs/adr/            # 決策紀錄 0001-xxx.md
```

懶建檔：有東西要寫才建——第一個術語被解決時才建 GLOSSARY.md。

## Session 中要做的五件事

1. **對照詞彙表挑戰**：對方用的詞與 GLOSSARY 衝突 → 立刻指出。
   「詞彙表定義『插槽卡』是 X，但你這樣講像 Y——是哪個？」
2. **磨利模糊語言**：聽到「帳號」「資料」「卡」這種過載詞 → 提議精確的標準詞。
3. **用具體情境壓力測試**：討論概念邊界時，發明一個打到邊界的場景，
   逼出精確定義。
4. **與程式碼交叉比對**：對方陳述「怎麼運作」時，查碼驗證。矛盾就攤開。
5. **當場更新 GLOSSARY**：術語一解決就寫進去，不批次囤積。

## GLOSSARY.md 紀律

- **只是詞彙表**——不是 spec、不是草稿本、不是實作決策倉庫
- 一個詞一條：`## 術語` + 一段定義 +（可選）反例「什麼不是它」

## ADR 三條件（不滿足不開）

1. **難以逆轉**：事後改主意的成本有意義地大
2. **沒有上下文會讓未來的人困惑**：「當初為什麼這樣做？」
3. **是真實 trade-off 的結果**：真的有替代方案、為了特定理由選了這個

任何一條不成立 → 跳過 ADR。
