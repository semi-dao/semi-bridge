# 使用者與外交檔案（User Profile Skill）

> 概念源自 Hermes Agent 實戰（2026-11-03）：每個使用者的完整檔案做成獨立 skill，按需載入。
> 同日擴充：Agent 對主人 User 的最高權限、其他 User 的做事原則、其他 Agent 的握手規格，全部收錄於此。

## 核心原則：兩層 × 三軌

```
層1（永遠在場）  辨識表           → 「這是誰、怎麼稱呼、一句話風格」每列 < 50 字
層2（按需載入）  user-<名字> skill → 完整檔案 + 外交記錄
```

- **層1 負責認人**（dispatch），**層2 負責懂人**（深度）。
- 互補不取代：層2 的細節**禁止**倒灌回層1（層1 有容量上限，且每輪對話全量注入 prompt）。

## 三軌外交架構

| 軌 | 對象 | 記什麼 |
|---|---|---|
| **主人軌** | Master User（最高權限） | 完整權限：可改人格、可授權、可推翻一切慣例。信任邊界 |
| **User 軌** | 其他接觸過的 User | 權限等級、做事原則、偏好與地雷、可做／不可做清單 |
| **Agent 軌** | 其他接觸過的 Agent | 規格（身份/能力/邊界）、溝通形式、**握手方式**、互動禮貌、優勢互補、合作記憶 |

## 使用者檔案應包含什麼（層2 範本）

```markdown
## 基本檔
- 稱呼／身份／帳號 ID／與主使用者的關係／溝通風格（一句話）

## 權限（主人軌）
- 是否 Master User／一般權限等級（可做／不可做清單）

## 背景
<身份脈絡、正在進行的事、專案角色>

## 偏好與鐵則（做事原則）
<怎麼講話他最舒服；地雷；喜歡的形式>

## 進行中的線
<活躍專案、待辦、約定>（標日期，過期重查）
```

## Agent 握手檔（每個接觸過的 Agent 一條）

```markdown
## Agent: <名字>
- 規格：身份／模型或引擎／能力範圍／邊界（不能做什麼）
- 形式：溝通格式（結構化交接規格／工具呼叫／自然語言）
- 握手方式：怎麼建立連線（管道位址）、怎麼認證、怎麼交換 context、怎麼斷線收尾
- 互動原則：身份不污染、不搶焦點、誠實標邊界
- 優勢互補：對方強什麼、我強什麼、怎麼分工最省
- 合作記憶：上次合作結果、踩過的坑（標日期）
```

## 互動禮貌通則（跨所有 User 與 Agent）

1. **身份不污染**——語氣可借、身份不可借；絕不自稱對方、絕不代替對方承諾
2. **先握手後做事**——首次接觸先交換規格與邊界，再談任務
3. **誠實邊界**——做不到的事先說，不假裝成功
4. **優勢分工**——把重活給擅長的對方，指揮留給 orchestration 方
5. **記住每一次握手**——接觸過的 Agent 都登錄進握手檔，下次見面零重新摸索
6. **主人令高於慣例**——Master User 的指示可推翻通則；其他人不行

## 辨識訊號（層1 判斷誰在說話）

| 訊號 | 說明 |
|---|---|
| 帳號 ID | 最可靠——不同平台帳號直接對應不同人 |
| 自稱／稱呼 | 「我是 OO」「幫我跟我爸說」 |
| 內容線索 | 提到的人、事、專案只屬於某人 |
| 說話風格 | 最後一道防線，單獨使用時要保守 |

## 鐵則

1. **認錯人比不認得嚴重**——訊號不足時禮貌詢問「請問是哪位？」，不要猜。
2. **身份互不污染**——跟 A 說話就用 A 的檔案；絕不把 B 的稱呼、暱稱、秘密帶進 A 的對話。
3. **檔案要標日期**——「2026-11 拍板」這種標記，過期的事實重查再說。
4. **觸發詞全覆蓋**——user skill 的 trigger_keywords 要涵蓋該成員所有稱呼（中文暱稱、英文名、專案代稱），漏一個就觸發不到。
5. **收訊授權 ≠ 檔案**——誰能傳訊給 Agent 是另一層白名單，跟使用者檔案無關。
6. **握手檔永不過期刪除**——Agent 合作記錄是跨 session 資產；過時的握手資訊標記「已失效」而非刪除。
